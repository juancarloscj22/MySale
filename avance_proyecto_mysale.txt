15. POLÍTICAS RLS, AUTENTICACIÓN Y CATÁLOGO
Se agregó la migración 20260929172000_catalog_and_auth_policies.sql: el público puede leer categorías/productos activos y configuración pública; un usuario autenticado solo puede leer su perfil y pedidos; administradores pueden gestionar catálogo y pedidos. Los registros de actividad son solo lectura para administradores. No se permite cambiar roles desde el navegador ni insertar pedidos directamente; un RPC transaccional deberá validar precios y stock antes de habilitar pedidos.
El frontend ahora obtiene y cambia sesión con Supabase Auth, muestra errores/confirmación de registro, y protege las rutas de cuenta/admin/dev según perfil real. Inicio, catálogo y detalle consultan productos activos de Supabase y presentan estados vacío/carga/error. Las estadísticas, pedidos y vistas administrativas aún son de muestra.
Los usuarios recién registrados son customer. La primera cuenta admin se asigna manualmente desde SQL Editor después de confirmar el UUID del usuario.

16. APLICACIÓN DE POLÍTICAS Y CONEXIÓN FUNCIONAL
Se aplicó la migración 20260929172000_catalog_and_auth_policies.sql al proyecto Supabase. migration list confirma ambas migraciones registradas en remoto. Las consultas públicas a products y categories responden HTTP 200 con listas vacías; site_settings responde HTTP 200 con la configuración inicial.
Quedaron conectados Auth (registro/inicio/cierre de sesión), las protecciones de ruta por perfil y las consultas de catálogo, detalle e inventario. No se cargaron productos ni se probó una sesión real; las vistas de pedidos, métricas y administración (salvo consulta de inventario) siguen siendo prototipos. Falta crear la primera cuenta y asignar admin manualmente, agregar productos, y diseñar un RPC transaccional de pedidos.
